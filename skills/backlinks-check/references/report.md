# Звіт backlinks-check

## Файл

`<робоча папка>\donors-<акцептор з дефісами замість крапок>-<дата>.xlsx`. Збирає `build_report.py` з `input.json`, `stage0–2.json`, `pages.json`, `site-notes.json`, `verdicts.json`. Усі аркуші: закріплений заголовок, автофільтр, числа числовим форматом.

### «Зведена» — усі домени

Порядок рядків: рекомендовані #1…#N (зелене заливання) → «резерв» → решта від найсильнішого. Під таблицею — рядок «РАЗОМ» із вартістю рекомендованих у грн.

| Стовпець | Звідки |
|---|---|
| домен | вхід |
| рекомендація | `verdicts.json` (за замовчуванням `recommendation_auto`): «РОЗМІСТИТИ #n», «РОЗМІСТИТИ — умовно, перевірити вручну», «резерв», «не брати»; після номера можна дописати примітку через « — » |
| вердикт | `verdicts.json`: сильний / середній / слабкий |
| головна причина | `verdicts.json`: одна фраза з цифрою |
| тип домену (TLD ринку / загальний) | скрипт |
| ціна, грн | вхід; порожньо, якщо ціни немає |
| ціна за 1K трафіку ринку, грн | скрипт; «не застосовно», якщо трафік ринку менший за 30 |
| ціна за 1K загального трафіку, грн | скрипт; лише для доменів не з TLD ринку |
| домени-донори, ранг, spam score | `backlinks_summary`, `bulk_spam_score` |
| тренд профілю 12 міс (dofollow) | скрипт: зміна, відхилення від медіани кандидатів, усі донори для довідки |
| трафік/міс ринку | сума за доступними мовами; розбивка за мовами — на аркуші «Метрики» |
| загальний трафік, частка ринку, % | запит без `location`; лише для доменів не з TLD ринку |
| країна аудиторії | `site-notes.json` + країна з найбільшим трафіком; примітка, що Росії в Labs немає |
| ключів у ТОП-10 (ринок) | `domain_rank_overview` |
| тренд трафіку 12 міс, тренд відносно медіани | `historical_rank_overview`; лише домени з TLD ринку |
| вихідні посилання і продаж | `verdicts.json` → `outgoing`; без нього — вихідних на сторінку зі скрипта |
| частка ризикових ніш у PR | `verdicts.json` → `risky_share`; без нього — з рекламного розділу в `pages.json` |
| тематика | `site-notes.json` → `topic` |
| топ-сторінки | топ-5 URL за трафіком і кількість ключів тематики в топ-100 |
| вже посилається на акцептор | скрипт: URL сторінки, rel, анкор, дата — або «ні» з покриттям списку донорів |
| розміщувались раніше | файл розміщень (дата, статус, ціна; «ВЖЕ В РОБОТІ») або `site-notes.json` → `placed` |
| перевірявся раніше | попередні `donors-*.xlsx`: дата і вердикт |
| примітка | `verdicts.json` → `note` |
| вердикт за правилами (auto), причина розбіжності | `stage2.json`, `verdicts.json` → `override_reason` |

Стовпці етапу 2 для відсіяних: «не перевірялось — відсіяно на етапі 1»; для доменів не з TLD ринку без історії трафіку: «не запитувалось — домен не з TLD ринку, скорочений обсяг етапу 2». Порожніх клітинок у цих стовпцях не лишати.

### Інші аркуші

- **«Метрики»** — довгий формат `домен | показник | період / деталь | значення | джерело`: поточні показники, трафік за мовами й ринками, SERP, помісячні ряди (dofollow-донори, усі донори, трафік, ТОП-10), розподіл топ-100 донорів за рангом, топ-10 донорів, топ-30 ключів, донори спам-зони.
- **«PR і ризики»** — `домен | URL | тип (PR / ризикова ніша) | зовнішніх посилань у тілі / у шаблоні | rel | тематика цілей`: розібрані статті, ризикові посилання на головній, останні матеріали рекламного розділу, знайдене пошуком (з позначкою «лише сигнал»).
- **«Витрати»** — `ендпоінт | запитів | прогноз $ | факт $ (за cost) | з кешу`; підсумок за полями `cost` і окремо **за балансом**.
- **«Аномалії»** — прапорці правил, недостовірні лічильники, перевірка спам-зони, SERP-завдання, що не повернулись, медіана тренду, примітки етапу 0 і записи з `verdicts.json` → `anomalies`.
- **«Ручна перевірка»** — домени з 403 (що відкрити, на що подивитись), записи `manual_check` із `site-notes.json`, статті, що не відкрились.
- **«Параметри»** — акцептор, ринок, location, google-домен, мови, тематика, дата, N, бюджет, кандидати, пороги, дата цін, TTL кешу, що не вдалося перевірити (`not_verified`), пропозиції до `rules.md` (`rules_proposals`).

## `verdicts.json`

```json
{
 "domains": {
  "site.kz": {"verdict": "середній", "reason": "одна фраза з цифрою", "recommendation": "РОЗМІСТИТИ #1",
              "override_reason": "", "outgoing": "", "risky_share": "", "note": ""}
 },
 "anomalies": [{"domain": "", "anomaly": "", "data": "", "conclusion": ""}],
 "not_verified": ["що не вдалося перевірити"],
 "rules_proposals": ["що змінити в rules.md"]
}
```

`build_report.py` не збирає файл, якщо: немає запису для домену; вердикт не з трьох дозволених; `reason` порожній, з кількох рядків або без цифри; `verdict` ≠ `verdict_auto` без `override_reason`; рекомендовано не кандидата, більше N, з пропуском чи повтором номерів; доменів не з TLD ринку серед рекомендованих більше половини N; домен із 403 має номер замість «умовно»; домен із прапорцем «не брати» рекомендовано без `override_reason`.

## Звіт у чаті

1. Скорочена таблиця: #, домен, вердикт, ціна, трафік ринку, ціна за 1K (ринку і загального), ранг, spam, тренд dofollow-донорів.
2. N рекомендованих — по одному абзацу: причина, ціна, головний мінус.
3. Вартість рекомендованих у грн. Якщо частина рекомендованих «слабкі» — окремо вартість без них.
4. Витрата DataForSEO за балансом (і сума `cost`, якщо відрізняється).
5. Що не вдалося перевірити.
6. Список ручної перевірки.
7. Розбіжності verdict / verdict_auto і рекомендацій — з виводу `build_report.py`.
8. Пропозиції змін до `rules.md`.

Після етапу 1 (зупинка): проміжна таблиця, витрата за балансом, кандидати й відсіяні з причинами, список 403.
