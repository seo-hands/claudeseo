# План ТЗ: `tz-<slug>-plan.json`

Скрипти не вигадують заголовки, питання FAQ, мета-теги й переклади. `plan_check.py --draft` пише `tz-<slug>-plan.draft.json`: у `_data` — усе, що потрібно для рішень (ключі з рівнями близькості, заборонені слова, сусідні сторінки, медіани, формула title, теми й прогалини, питання FAQ конкурентів, кандидати в семантичні слова). Claude заповнює поля нижче за `rules.md` і зберігає файл як `tz-<slug>-plan.json`. `_data` у готовому плані не потрібен.

| Поле | Зміст |
|---|---|
| `page`, `slug`, `page_kind` | URL, slug, `commercial` (за замовчуванням) або `info` |
| `doc_title`, `header` | заголовок документа і 1–2 вступні рядки (сторінка, мова, на чому заснований аналіз) |
| `goal` | розділ 1: мета, аудиторія, інтент, тон — список пунктів |
| `volume` | `range: [від, до]` символів без пробілів, `words` (текстом), `why` — пояснення вибору |
| `structure` | блоки по порядку: `level` (`H1`, `intro`, `listing`, `H2`, `H3`), `heading`, `chars: [від, до]` або `null`, `topic`, `note` (що писати) |
| `structure[].topic` | id теми з чернетки (`subtopic:<назва кластера>` або `block:faq` / `block:regions` / `block:seasons`), рядок або список; за ним ставиться «у N з M» і позначка прогалини |
| `structure[].clusters` | список id кластерів етапу 1 (`["K07"]`), які закриває цей H2 або H3; за ним ставиться позначка «обов'язковий за ключами». Кожний кластер сторінки (`_data.clusters_must_have_own_h2_or_h3`) має бути хоча б в одному H2/H3 |
| `faq` | `[{q, note}]` — питання мовою сайту і звідки воно |
| `exact_text` | місця точних входжень головного ключа в тексті (заголовки й FAQ скрипт рахує сам) |
| `keywords` | для кожного ключа сторінки: `place`, `count`, `block`, `why` |
| `keywords_intro`, `keywords_note`, `diluted_forms` | необов'язкові уточнення до розділу 5 і список розбавлених форм |
| `lists`, `tables`, `photos` | розділ 4: пункти списком |
| `terms` | `{термін у нижньому регістрі: {uk, where, name?}}` — семантичні слова, що йдуть у ТЗ; ключ — як у `term_candidates` |
| `terms_skip` | кандидати, які свідомо не беремо (дублі, штампи, уривки) |
| `links` | `[{page, anchors: [a, b], where}]` для сторінок із розподілу; `links_extra` — інші сторінки сайту (`state`); `links_skip` — `{сторінка: причина}` |
| `bans` | додаткові заборони для цієї сторінки (загальні скрипт пише сам) |
| `competitors_better`, `how_to_beat` | розділ 9 |
| `meta.A` | `title`, `description`, `h1` — кожне `{text, why}`; `condition` |
| `meta.tests` | `[{name, condition, title, description, h1}]` — комплекти для тесту після 8–12 тижнів |
| `meta.note`, `meta.current_notes` | примітка до мета-тегів і коментарі до рядків «Зараз на сайті» |
| `developer` | додаткові пункти розділу 11 (типові скрипт збирає сам) |
| `subtopics_uk` | переклади назв підтем українською |
| `gaps_declined` | `{id теми: причина}` — прогалини, які свідомо не включено в структуру |

Перевірки `plan_check.py` (помилка зупиняє збирання): порядок блоків; ліміт і розподіл точної форми; заборонені слова в title і заголовках; окремий H2 під тему інформаційної сторінки; діапазон обсягу і сума блоків; довжини й символи мета-тегів; узгодженість title–H1; місце кожного ключа; кожний кластер етапу 1 закрито власним H2 або H3; усі прогалини в структурі або відхилені; посилання на всі сторінки розподілу, по два анкори; переклади термінів; джерело кліматичних даних.
